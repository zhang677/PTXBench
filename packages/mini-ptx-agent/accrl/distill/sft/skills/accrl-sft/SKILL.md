# AccRL SFT

## Scope

Use this skill for AccRL distill-to-SFT work in `/home/chengze/work/AccRL`:

- Build controlled SFT parquet files from distill `reasoning_pairs.jsonl`.
- Compare reasoning generated by different models from the same source turns.
- Launch Qwen SFT through the Miles Docker/Podman image.
- Debug W&B, Ray, checkpoint conversion, OOM, and NaN-gradient failures.

## Data-Build Workflow

Prefer the controlled intersection builder when comparing two reasoning sources:

```bash
GLM_DIR=/path/to/glm_experiment \
KIMI_DIR=/path/to/kimi_experiment \
OUT_DIR=/path/to/sft_data \
  ./accrl/distill/sft/scripts/build_intersection_sft.sh build
```

This writes:

```text
glm_intersection.parquet
kimi_intersection.parquet
mixed_intersection.parquet
manifest.json
length_stats.json
```

The canonical identity is:

```text
(exp_id, definition_name, turn)
```

The builder must keep only common keys whose `system_prompt` and `input` are identical. This keeps the experiment scientifically clean: the prompt/context is fixed and only the assistant reasoning target differs.

Use `reasoning` as the assistant target by default. In current Qwen3.5 SFT, wrap it as:

```text
<think>
{row["reasoning"].strip()}
</think>
```

`row["reasoning"]` is the visible `<my_reasoning>...</my_reasoning>` extracted from GLM/Kimi output. `row["thinking"]` is the teacher model's hidden scratchpad and is not used unless the user explicitly asks for a separate thinking-field ablation.

## Data Checks

After every data build, inspect the manifest and length stats:

```bash
/home/chengze/micromamba/envs/dev/bin/python - <<'PY'
import json
from pathlib import Path
base = Path("/path/to/sft_data")
manifest = json.load(open(base / "manifest.json"))
stats = json.load(open(base / "length_stats.json"))
print({k: manifest[k] for k in ["num_glm_records", "num_kimi_records", "num_common_keys", "num_kept_keys", "num_dropped_common_keys"]})
for name in ["glm", "kimi", "mixed"]:
    print(name, stats[name]["num_rows"], stats[name].get("total_tokens"), stats[name]["source_counts"])
PY
```

If token stats look implausible, fix the tokenizer/stat code before trusting the report. A prior bad report showed all token lengths as `2`; that was invalid.

Long samples may require context parallelism. Do not assume a parquet is trainable until checking p90/p95/max total token lengths.

Before training a rebuilt SFT parquet, verify the Qwen chat template and Miles qwen3 mask:

```bash
NUM_SAMPLES=8 PREVIEW_RADIUS=8 \
  ./accrl/distill/sft/scripts/verify_sft_target.sh run
```

Expected verifier signals:

```text
prompt_tail ends with <|im_start|>assistant\n<think>\n
<think> has loss_mask=0
first loss token is the first reasoning token
</think> has loss_mask=1
visible_after_think_tokens=0
```

It is expected that Qwen template tokens after `</think>`, such as `<|im_end|>`, may be supervised by the qwen3 loss mask.

## Training Workflow

Use the Miles image through the SFT launcher:

```bash
MODEL_PRESET=qwen35-9b \
SFT_DATA=/path/to/data.parquet \
OUT_FOLDER=/path/to/output \
MASTER_ADDR=127.0.0.1 \
WANDB_GROUP=<clear-run-name> \
  ./accrl/distill/sft/scripts/qwen3.5-9b_sft.sh run
```

For long reverse-CoT samples, prefer:

```text
CP_SIZE=8
SFT_BATCH_SIZE=1
MAX_TOKENS_PER_GPU=16384
RAY_NUM_CPUS=16
```

For a cautious resume after instability:

```bash
SKIP_NAN_STEPS=0 LR=1e-6 \
SFT_DATA=/path/to/data.parquet \
OUT_FOLDER=/path/to/output \
MASTER_ADDR=127.0.0.1 \
WANDB_GROUP=debug-lr1e-6 \
  ./accrl/distill/sft/scripts/qwen3.5-9b_sft.sh run
```

For an overfit sanity check, use the reusable harness mode instead of hand-editing the low-level launcher. It trains from fresh by default, disables eval, removes warmup, and uses a constant LR:

```bash
DATASET=mixed \
MODEL_PRESET=qwen35-9b \
OVERFIT_ROWS=4 \
LR=1e-5 \
  ./accrl/distill/sft/scripts/run_sft_experiment.sh overfit
```

If `train/loss` does not fall after the same rows repeat, debug data/mask/LR before launching a long run. Across different long rows, early loss can be noisy; compare repeated rows or epoch-level averages.

Optimizer schedule knobs are explicit:

```text
LR_DECAY_STYLE=cosine       # overfit mode default: constant
LR_WARMUP_FRACTION=0.1      # overfit mode default: 0
MIN_LR=1e-7                 # overfit mode default: 0
```

For the current long mixed GLM/Kimi reasoning SFT harness, prefer `run_long_sft_mixed.sh`. It sets conservative long-run defaults and then delegates to `run_sft_experiment.sh`:

```bash
MODEL_PRESET=qwen35-9b \
RUN_TAG=<clear-run-tag> \
CP_SIZE=4 \
SFT_BATCH_SIZE=1 \
MAX_TOKENS_PER_GPU=32768 \
LOG_PROBS_CHUNK_SIZE=128 \
LR=1e-6 \
SKIP_NAN_STEPS=0 \
SFT_WANDB_TOKEN_TABLE_EVERY=50 \
SFT_WANDB_TOKEN_TABLE_RADIUS=24 \
  ./accrl/distill/sft/scripts/run_long_sft_mixed.sh run
```

For a first sanity run, set `SFT_WANDB_TOKEN_TABLE_EVERY=1` and stop after W&B shows the first rollout table.

For sequential GLM-only, Kimi-only, and mixed full runs, use the consolidated suite command instead of adding a separate shell script:

```bash
MODEL_PRESET=qwen35-9b \
DATASETS="glm kimi mixed" \
BASE_TAG=<clear-suite-tag> \
  ./accrl/distill/sft/scripts/run_sft_experiment.sh suite
```

For Qwen3.5-35B-A3B, convert the model once after the HF download completes:

```bash
MODEL_PRESET=qwen35-35b-a3b \
  ./accrl/distill/sft/scripts/convert_qwen3.5-9b_model.sh convert
```

Then run a train-only overfit smoke before a long run. For 35B, overfit mode uses eight tiny synthetic rows by default, `CP_SIZE=1`, `EP_SIZE=8`, disables checkpoint saves, disables eval, disables weight decay, and uses constant LR. This is a pipeline sanity check: it proves the Qwen chat template, Miles qwen3 mask, Megatron train path, and W&B logging can drive `train/loss` down without long-sequence instability. Do not use context parallelism for this tiny sanity data; CP can leave ranks with no supervised tokens.

```bash
MODEL_PRESET=qwen35-35b-a3b \
DATASET=mixed \
  ./accrl/distill/sft/scripts/run_sft_experiment.sh overfit
```

To overfit real rows instead, set `OVERFIT_SOURCE=dataset`; for 35B this currently uses the two shortest real rows and is more likely to expose long-sequence numerical issues than a pure pipeline sanity check.

The 35B overfit mode sets `SAVE_CHECKPOINTS=0` by default so a tiny smoke run does not write hundreds of GB of optimizer checkpoint state. Enable checkpointing explicitly for long runs.

To log to public W&B instead of Meta W&B, use the public API host, set the entity/team, and log in to that host first:

```bash
with-proxy wandb login --host=https://api.wandb.ai

WANDB_HOST=https://api.wandb.ai \
WANDB_TEAM=zhichenzeng_zzz \
WANDB_PROJECT=qwen35-35b \
  ./accrl/distill/sft/scripts/run_sft_experiment.sh print
```

`WANDB_ENTITY` is accepted as an alias for `WANDB_TEAM`; Miles passes this value as `wandb.init(entity=...)`.

For a full 35B train-only run:

```bash
MODEL_PRESET=qwen35-35b-a3b \
WANDB_HOST=https://api.wandb.ai \
WANDB_TEAM=zhichenzeng_zzz \
WANDB_PROJECT=qwen35-35b \
DATASET=mixed \
NUM_EPOCH=30 \
LR=1e-6 \
CP_SIZE=4 \
EP_SIZE=8 \
SFT_BATCH_SIZE=2 \
GLOBAL_BATCH_SIZE=2 \
MAX_TOKENS_PER_GPU=32768 \
SAVE_CHECKPOINTS=1 \
  ./accrl/distill/sft/scripts/run_long_sft_mixed.sh run
```

tail -n 200 /path/to/run/experiment_harness/train.log
perl -ne 'if (/eval (\d+): .*?generated_thinking\/mean'\''\: ([0-9.]+).*?generated_visible_after_think\/mean'\''\: ([0-9.]+).*?response_len\/mean'\''\: ([0-9.]+).*?truncated_ratio'\''\: ([0-9.]+)/) { printf "eval=%s thinking=%s visible=%s response=%s truncated=%s\n", $1,$2,$3,$4,$5 }' /path/to/run/experiment_harness/train.log

Use Meta W&B:

```text
https://meta.wandb.io
```

The launcher should mount:

```text

/home/chengze/.config/wandb -> /root/.config/wandb
```

It should also forward proxy env vars into the container and Ray workers. If W&B is suspicious, run a container smoke test before a full SFT job.

Current SFT rollout metrics to check:

```text
rollout/thinking/mean
rollout/thinking/p90
rollout/thinking_end_ratio
rollout/thinking_missing_end_ratio
rollout/visible_after_think/mean
rollout/sft_token_mask_table
```

For pure `<think>{reasoning}</think>` SFT, expect `rollout/thinking_end_ratio=1`, `rollout/thinking_missing_end_ratio=0`, and `rollout/visible_after_think/mean=0`. The W&B token table is target/mask debugging, not model predictions; SFT rollout does not have logits.

Current SFT eval is free-generation eval, not teacher-forced per-token-loss eval. By default the harness sets `SFT_EVAL_TURNS=/home/chengze/work/AccRL-exps/distill/gemini_turns_0422.jsonl`; `prepare_sft_eval_prompts.py --turns` reconstructs the original Gemini policy conversation up to the current turn, then stores the SFT assistant target under `target` only for W&B table comparison. Metrics such as `eval/sft/generated_thinking/mean`, `eval/sft/response_len/mean`, and `eval/sft/truncated_ratio` describe what the model generated; they do not compute `P(target | prompt)`. Qwen3.5's native generation prompt already ends with `<think>\n`, so do not append another `<think>` in eval code.

## Debugging Rules

Ray Jobs may fail through an IPv6 dashboard JobAgent. Prefer the local Ray driver path implemented in `qwen3.5-9b_sft.sh`.

If Ray workers cannot import `megatron.training`, ensure `PYTHONPATH=/root/Megatron-LM/` is passed through Ray `runtime_env`.

If the container crashes with `pthread_create failed` or OpenBLAS thread errors, confirm Podman uses:

```text
--pids-limit=-1
OMP_NUM_THREADS=1
MKL_NUM_THREADS=1
OPENBLAS_NUM_THREADS=1
NUMEXPR_NUM_THREADS=1
```

If training OOMs on a long sequence, do not only lower batch size if it is already `1`. Use context parallelism:

```text
CP_SIZE=8
--allgather-cp
```

If gradients become NaN:

1. Treat it as a training/data issue, not a W&B or container issue.
2. Check the previous rollout's `total_lengths`, `response_lengths`, `train/loss`, and `train/grad_norm`.
3. Resume from the last checkpoint with lower LR and `SKIP_NAN_STEPS=0` first.
4. Use `SKIP_NAN_STEPS=1` only after deciding that skipping occasional NaN steps is acceptable.

Miles' `--no-check-for-nan-in-loss-and-grad` can keep a long job alive, but it can hide data or optimization problems. Do not use it as the first diagnostic move.

## Scientific Hygiene

- Preserve raw source paths and SHA256s.
- Keep model-specific and mixed datasets separate.
- Keep `manifest.json` and `length_stats.json` next to every parquet.
- Report parquet SHA256s in experiment notes.
- Do not silently mix `reasoning` and `thinking`.
- Do not compare runs unless data path, checkpoint, LR, CP size, batch size, and W&B group are known.
- Record both the AccRL commit and nested Miles commit in experiment manifests/notes.
